Facts for wasmext: a 1.5 MB module gave 27 MB of C in 12 parts and a 42 MB extension; **there is no way to grow a memory from Python**, so the module's initial memory was raised in the WAT (1024 to 6144 pages); the table is reachable from Python (`inst["G"].get(i)(...)`).

## Where the traps are (short; the long version is in the experiment READMEs)

* wasm3 slots are **4 bytes** (`m3slot_t = u32`), the metacode stream words are 8 bytes.
* A CoreMark run is valid only for at least 10 s of the guest clock; take speeds from the **host** clock on JSC and wasm3 (the guest clock disagrees).
* `__DONE__`-style end markers must be matched anywhere in the output; a missed one makes a timeout look like a measurement.
* In wasmhost the tests are run by CI; do not run the whole suite locally unless a failure needs reproducing. In wasmext run the suites listed in `CLAUDE.md` before a push (this branch is docs only).
