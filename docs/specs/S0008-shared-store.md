# S0008 Shared store across separately built artifacts

## Summary
Today a store links only instances made by the same artifact (one `.so` / `.pyd` / `.dll`, which has its own copy of the wasm2c runtime).
Step 8 lets artifacts built apart attach to one store and link, share tables, tags and references, and trap and throw across each other.
This changes the contract of the store, of the entry macros and of the exception functions, so it needs this spec approved before code.

> **Status of the parts.** 8a (record, attach, links, references, host tags) is `approved` (2026-10-30) and built. **8b (the runtime of the store) is a draft and waits for the maintainer's approval**: the section "Step 8b" below and every line marked "(8b draft)" elsewhere in this file. No code of 8b is written before the maintainer approves it explicitly.

Facts that bound the design (checked in the code and in the runtime sources of wasm2c 1.0.42):
1. Each artifact has its own `g_wasm_rt_jmp_buf`, unwind target, exception state, depth counter and stack limit. Today the generated entries
   (`WASMEXT_ENTER_REENTRANT/PLAIN`) write only the artifact's own copy, so a trap in another copy's code cannot reach the entry.
2. The exception state in the stock runtime file is a `static` thread-local per copy: a `try` in B never catches a throw from A.
3. The store code is `static inline`, so B works directly on A's store struct (mutex, registry, arena). Attach is safe only with an identical layout.
4. The store calls function pointers of the artifact that added a member, at close, from whichever copy runs `close`.
5. Trampolines alone do not work: re-raising a trap in "the caller's copy" needs the same per-thread shared state as option (b) of TABLES_PLAN.

## Goals / Non-goals
* Goals: attach with a checked record; links, tables, tags, externref and funcref across artifacts; a trap or a throw in one copy reaches the
  innermost entry or `try` of the thread; serials that differ between the stores of one runtime and almost never collide between runtimes (8b draft, D-3: the 8a counters collide for certain, see Step 8b); close and free from either copy; a measured hot path.
* Non-goals: detaching before `store_free`; Pyodide and Android runs (until the emulator task);
  typed host functions with references (FFIs cannot pass structs by value; they use the uniform shape).

## Interface (proposed, recommended design 1)
* The **runtime of a store**. Every artifact keeps a full copy of the runtime (autonomy: one module needs nothing outside it) and uses it for the stores
  it makes itself. A store points at its runtime (`store->rt`, `wasmext_runtime`: a versioned table of the functions the code of an instance calls: trap,
  throw and catch with the exception state, allocate/grow/free of memories and tables, the stack check, the serial counter) and holds the per-thread stack
  of entries. An instance of any artifact made in that store runs on that runtime. `wasmext_artifact` (per artifact: `thread_ready`, `thread_free`, `depth`)
  lets the store make a foreign copy ready on a thread. The table only grows at its end.
* (8b draft: renamed and detailed in Step 8b) `WASMEXT_ENTER_STORE` / `WASMEXT_LEAVE_STORE` (not `..._SHARED`: that name exists in the legacy glue, `wasmext_glue.h:353`) replace REENTRANT/PLAIN in all generated code; inline when the store runs on the runtime of the artifact itself.
  `enter` sets the active runtime of the thread from `store->rt` and `leave` restores the previous one and the saved unwind target (not `prev->buf`).
* (8b draft) The text above about `wasmext_artifact` (`thread_ready`, `thread_free`, `depth`) and about "the stack check" in the table is not what 8b builds: the 8a code has only the identity of an artifact (`wasmext_artifact_`, a `char`) and a list of those addresses; 8b makes the list a fixed array of `{identity, activate, deactivate}` (D-4, D-5), and the stack check is an inline variable of each copy, not a function of the table (D-7).
* A fixed header at the start of `wasmext_store`: `{size, abi, floor, layout, runtime, flags, rt}`. `int wasmext_store_attach(wasmext_store *s, char *why, size_t cap)`;
  new code `WASMEXT_STORE_INCOMPATIBLE`. `attach` refuses (reason in the caller's buffer) when x differs or below `floor`, `size` differs, `layout`
  (hash of sizes and offsets of store, registry, slot, owner ops, arena node, rlock, instance, host func, extern, `WASMEXT_NO_THREADS`, `_MSC_VER`)
  differs, `runtime` differs (code `WASMEXT_STORE_INCOMPATIBLE`), the creator was built without the trap handler (8b), or the store is closed (code `WASMEXT_STORE_CLOSED`, built so in 8a-1). (8b-2: or a call is in flight on the store, code `WASMEXT_STORE_BUSY`, because that call would never activate the new copy.)
* `wasmext_store_new` takes the serial from the runtime of the store (`rt->next_serial()`); the per-artifact `wasmext_store_serial_` goes away. (8b draft, D-3: the counter of a runtime starts at a value derived from the address of its table, so serials of stores of one runtime differ and those of two runtimes collide with a chance of about 1 in 65536 per pair; layer 3 gives a process-wide counter through its capsule.)
  `wasmext_instance_new` refuses a store this artifact did not make or attach (`EXDEV`).
* `_natify` `_RUNTIME_WRAPPERS`: `impl` always defines `WASM_RT_TRAP_HANDLER`; `exceptions` renames the seven functions of the exceptions file to
  `wasmext_own_*` and defines the real `wasm_rt_*` names as forwarders to the active runtime (a wrapper in the manner of D6; the toolchain file is untouched).
  (8b draft: today `impl` defines `WASM_RT_TRAP_HANDLER` only `#ifdef WASMEXT_TRAP_HANDLER`, a macro of the old layer 3, `_natify.py:403`; D-2 and D-6 widen the renaming to every runtime function that generated code or the core calls, and make it unconditional for the core.)
* Signature letters `F` (funcref) and `E` (externref) replace `r` in `wasmext_export.signature`; shims and typed slots with references pass
  `wasm_rt_funcref_t` by value and `void *` (built in 8a-2; typed host functions with references stay refused).
* `int wasmext_tag_new(wasmext_store *s, const uint8_t *types, uint32_t n, wasmext_export *out)`: a host tag that **belongs to the store** (a member of kind
  `WASMEXT_KIND_TAG`, freed at close; see Decisions item 3 and 8a-3 under Changes). `bind_export` accepts it only for an instance of the same store.
* Discovery: the host passes the `wasmext_store *`; in layer 3 a capsule `wasmext.store.v<X>` carries the same pointer. No named symbol.

## Semantics
* No artifact is bound for life. An instance runs on the runtime of the store it was made in; the `wasm_rt_*` of every copy (the `exceptions` wrapper, `WASM_RT_TRAP_HANDLER`) forward to the active runtime of the thread. A call that passes through instances of two stores (a host function in between) has one active runtime at a time, each store's own entry stack.
* Through a table (raw call B to A): no store enter; a trap anywhere goes to the active runtime's trap and then to the innermost entry; a throw goes to the
  innermost `try` of any copy.
* Typed HOST functions with references are refused by `bind_typed`; a sealed record built by a C host is trusted C (`bind_export` compares letters and refuses an unknown one, not the code behind the address).
* Through a link: B's forwarder calls A's shim (nested enter); LINKED+code is re-raised in B. (8b draft, 8b-5, decided in Decisions item 6: an exception that nothing caught in A is re-thrown in B; S0007 is changed first.)
* Every copy that has an instance in the store is made ready on the thread at the first entry (stack limit and `wasm_rt_init_thread`). With depth counting
  (Windows, Emscripten) the entry saves and restores the counters of those copies.
  (8b draft, D-7: only the runtime of the store calls `wasm_rt_init` / `wasm_rt_init_thread` on a thread; the other copies have their inline state synchronised, the stack limit variable and the depth counters. The text above is replaced by Step 8b.)
* Every attached artifact stays loaded until `wasmext_store_free` returns (D46 rule 5: the store keeps the code it runs). Today this is the host's duty: `attach(s, why, cap)` only records the artifact in the store and has no unload hook. The decision of D46: `attach` takes a reference on the artifact, which the store drops after the last member is freed; for a Python extension this costs nothing, for a C host it needs an unload-hook parameter in `attach`. That is the planned step **8c** (after 8b-7, below), not part of 8b.
* Imported tag cell stays one per (artifact, module) per process (D34); the store that holds a host tag clears the cells it was given when it closes (8a-3).
* The binding of an instance to a runtime is explicit and by store: whoever calls `wasmext_store_new` makes the store and its runtime, and any other artifact
  joins it only by `wasmext_store_attach`. Several stores can live in one process, each with its own instances, runtime, host and state, and nothing is
  shared between stores (a link, a table, a reference or a funcref of another store is refused, as today). One leak is known and comes from wasm2c, not from
  the design: an imported tag is a process-global symbol, so its cell is one per (artifact, module) per process (D34) and two stores that import the same
  tag get the same tag. Open question 5 is about this.
* The model is that of Wasmtime: a store is the one place where the runtime, the host (WASI state: descriptors, arguments, environment, preopens) and the
  state of its members live, and the instances of one or several modules (of any artifact) in it share all three. What differs from Wasmtime is only how the
  runtime is distributed: not one library, but a copy inside every artifact, of which the copy of the artifact that made the store is the one in use.
  A module that is alone needs nothing outside itself. The host of the store is reached through the store by an instance of any artifact; its layout is
  part of what `attach` checks (`layout` of `wasmext_host`, P1 bit, fusedwasi version, all in the one `host_layout` word). `docs/architecture.md` says "the state of WASI never crosses
  (opaque)"; that line is older and is superseded by this section, and needs a new Dn.

* The hashes of the layout rest on a hand-written list of the fields of each struct (`WASMEXT_LF_` in `wasmext_store.h`, `wasmext_instance.h`, `wasmext_host.h`), each struct salted with a constant of its own: a new field of a listed struct, or a new struct that another copy reads inline, must be added to the list, and a test in `tests/test_artifacts.py` swaps fields to prove the list is followed. What is hashed of the structs of fusedwasi (the state, the stream, the preopen) is their size, the preopen's fields and the switches of the build (`WASMEXT_HOST_P1`, the bits of a handle); the version of fusedwasi is in it as `WASMEXT_FUSEDWASI_VERSION`, a macro whose value the Python package computes (FNV-1a 32 of the installed version string, `fusedwasi_version_macro` in `_natify.py`) and passes to the compiler, because the headers have no version (`fusedwasi.h` names a `<fusedwasi/version.h>` that the installed tree lacks). A build without the macro (plain C) hashes 0, so it differs from a product build, by intent; if the version cannot be read the macro is not defined.
* The functions that add to a store on behalf of the calling artifact (`instance_new`, `tab_new`, `extern_new`, `store_own`, `store_adopt`, `store_register`, `store_set_host`) refuse a store that this artifact neither made nor attached to, before they touch anything past the head (EXDEV for the two that answer an errno; `WASMEXT_STORE_INCOMPATIBLE` for the store functions; `WASMEXT_INST_BAD_ARGS` for `extern_new`).

### Known limit of 8a-1 (fixed by 8b)
> (8b draft) The mechanism below is corrected in "Corrections of the text of 8a" under Step 8b: only the `stock` and `guard` modes leak; the core had no stack limit and no handler; D-7 and 8b-3 fix it.

* A trap (a signal included) in code of one copy while two copies are in one store aborts, or jumps into the stale buffer of the other copy. Seen in review: a guard-page access in `w2c_liba_load` ran the handler of signals of `libartifact_b`, which called its own `wasm_rt_trap`, found no entry and aborted (SIGABRT). Each copy has its own `g_wasm_rt_jmp_buf`, unwind target and handler, and the handler that runs is that of the copy that installed its chain last. 8a-1 therefore tests no trap across artifacts; the traps of one copy alone are as before.
* Requirement for 8b: a thread that calls into two copies leaks one alternate stack. Each copy of the runtime allocates and installs its own `sigaltstack` in `wasm_rt_init_thread`; the second replaces the first, and `wasm_rt_free_thread` of a copy frees its stack only if it is the one in place (the other is reported as "alternate stack was modified unexpectedly" and kept, so LeakSanitizer reports it). The readiness of the copies of a store on a thread (`thread_ready` and `thread_free` of all of them, in the reverse order) must be made one operation in 8b.

### Known limits of 8a-3
* `wasmext_instance_bind_export` checks `wasmext_store_closed` once, without the lock, and then reads exporter memory and table limits (`pages`, `max_pages`, `size`, `max_size`) without it: a `store_close` of the EXPORTER's store that runs at the same time is a use-after-free for memory and table records (found in review; read from the code, not reproduced). The tag path is fully under the lock. Binding in a store while it is being closed is a misuse of the host API, as for the other kinds; fixing it means taking the store lock for those reads, a separate step.
* The race tests of host tags are statistical and take time (plain 11 s, TSan 54 s, ASan+UBSan 87 s on 4 cores). The order of `own` and `register` in `wasmext_tag_new` is guarded by TSan only (ASan does not see it). TSan runs in the Python versions workflow (ubuntu, 3.15 and 3.15t) and in Coverage, not in Sanitizers (which sets ASan flags and skips that test).
* Another copy of the core (an artifact that attached to the store) reallocs the list of cells `t->cells` that the copy that made the tag frees. This is fine with one libc; with separate CRT heaps (Windows, two DLLs) it is not. The registry has the same limit.
* A thread-local exception can keep the address of the tag of a closed store. The address is only compared (identity of the exception), never dereferenced.

## Step 8b: the runtime of the store

> **8b: approved by the maintainer on 2026-11-02** (with the recommendations of the orchestrator on the seven questions: the stop rule covers cases 1, 2, 7 and 8; the builders of the core always define `WASMEXT_STORE_RUNTIME` and the core headers `#error` without it; the handler and the stack limit go to a file of their own; `flags` of the runtime table carries the mode of the stack check and `attach` refuses a mismatch; `wasmext_pending_throw_` stays per copy with the rule and the refusal). Written 2026-11-02 before that approval as a draft: Written 2026-11-02 from the plan of the orchestrator and the maintainer's decisions of that day. Every statement about the code below was read in the code on that day (file:line given); nothing of 8b was built or run. `D-n` here are the decisions of 8b in this file; `Dn` are the records in `docs/DECISIONS.md` (D40 to D45).

### What the code is today (read 2026-11-02)
* **Entry.** `WASMEXT_ENTER_REENTRANT/PLAIN` (`wasmext_glue.h:337-350`) set the jump buffer and the unwind target of the copy they are compiled in, and no other. They are emitted by `_binding.py` for the adapters (`:112-118`), `instantiate` (`:404-405`) and the shim (`:517-528`). The legacy shared stack of entries (`wasmext_traps`, `wasmext_glue.h:239-316`, `WASMEXT_ENTER_SHARED` `:353-362`) exists only under `WASMEXT_TRAP_HANDLER` and serves the old layer 3 (`_gen.py:782`, `_shared.py:606`, `_exe.py:437`, `_natify.py:992`); the core does not use it and the tests of the core do not define the macro.
* **Unwind target.** `LEAVE_REENTRANT` (`:346`) puts back the jump buffer and not the unwind target; the legacy `leave` sets it to `prev->buf` (`:283`). Either way an enclosing wasm `try` loses its target after a nested entry (read from the code, not reproduced). The new `leave` restores the target that was saved at `enter`.
* **Thread set-up.** `wasmext_thread_ready` (`wasmext_instance.h:175-181`) calls `wasm_rt_init()` once per copy per thread, from `wasmext_instance_begin_` (`:704`), `instantiate` (`:771`), `instance_call` (`:979`) and `call_ref` (`:1018`). `wasmext_thread_free` is `:182-187`. The core has **no stack limit and no handler of signals**: `src/wasmext/c/` has no `sigaction` and no `wasmext_stack_limit` except a comment (`wasmext_store.h:101`). Both live in `_gen.py` (the chain handler `:797-865`, the limit `:879-906`) and in the wrappers of `_natify.py:403-410`. So with the product flags (`signal_build_flags`, `_natify.py:437`) the runtime installs no handler and the core sets no limit: a recursion or a guard-page access in a core test is not turned into a trap.
* **The store.** The head has `void *rt`, reserved and NULL (`wasmext_store.h:122`). The artifacts are a `realloc`ed `const void **` list under the mutex (`:136-137`, `:188-201`, read under the lock in `:228-236`). The serial is a per-artifact counter `wasmext_store_serial_` that starts at 0 (`:94-96`, `:213`): **the first store of every artifact gets serial 1, so two artifacts collide for certain today**, not by chance (the registry keeps 16 bits, `wasmext_registry.h:80,182`). 8a built no test of serials.
* **The runtime of wasm2c (1.0.42).** `g_unwind_target`, the active exception and its size are `static` thread-local variables in `wasm-rt-exceptions-impl.c` (`g_unwind_target` at line 29): nothing outside that file can reach them, which is why the wrapper must define the accessors in the same translation unit. The funcref and externref table functions and `wasm_rt_trap` are in `wasm-rt-impl.c`; the exnref table functions are in the exceptions file (`#include "wasm-rt-impl-tableops.inc"` with `WASM_RT_TABLE_OPS_EXNREF`); the memory functions, plain and `_shared`, are in `wasm-rt-mem-impl.c`. The alternate stack is allocated only under `WASM_RT_STACK_EXHAUSTION_HANDLER` (`wasm-rt-impl.c:78`, `:315`), which `NONCONFORMING_UNCHECKED_STACK_EXHAUSTION` (the product's `limit` mode) turns off. `wasm_rt_trap` restores `wasm_rt_call_stack_depth` from `wasm_rt_saved_call_stack_depth` (`:92`).
* **The wrapper `mem`** tests `strncmp(where, "wasm_rt_allocate_memory", 23)` on `__func__` (`_natify.py:416`); after the rename the function is `wasmext_own_wasm_rt_allocate_memory`, so the compared name and its length must change (the plan's claim holds). `__func__` is the name of the function as defined, not the macro's old spelling.

### Decisions of 8b (the maintainer, 2026-11-02)
* **D-1 (C1). The core carries the stack limit and the chain handler.** Both are copied into the layer-1 core from `_gen.py` (`:879-906` the limit init under `WASMEXT_STACK_LIMIT`; `:797-865` the chain handler of SIGSEGV/SIGBUS), because the core must work with no Python and no layer 3. Layer 3 keeps its copy until it moves onto the core; both are rows of the register of duplicates in `docs/layers.md`. Record: D43.
* **D-2 (C2). Forwarding is unconditional for the core.** The runtime functions are renamed `wasmext_own_*` and the real `wasm_rt_*` names are forwarders in every build that uses the core: the core tests, the core artifacts, the product builds of the core. The build macro `WASMEXT_STORE_RUNTIME` stays **only** as a transition switch for the OLD layer 3 (`_gen.py`, `_shared.py`, `_exe.py`, with `wasmext_traps` and REENTRANT/PLAIN): a build that does not define it gets the wrappers as today. It disappears when layer 3 moves onto the core. Meaning for the code: every builder of the core (the fixtures `build` and `build_artifact`, and later `_natify` for the core) defines it, there is no way for a user of the core to leave it out, and the core's headers `#error` without it; the old layer 3 builds are the only ones that do not define it. The entry macros are `WASMEXT_ENTER_STORE` / `WASMEXT_LEAVE_STORE`. Record: D42.
* **D-3 (C3). Serials come from a counter of the runtime, seeded from the address of its table.** A collision between stores of different runtimes is possible (about 1 in 65536 per pair) and matters only when a host hands a handle to the wrong store, which is a misuse the registry then answers wrongly instead of `WRONG`. Layer 3 will give a process-wide counter through its capsule. The test of serials fixes the seeds with a hook, so that it is deterministic. Record: D45.
* **D-4 (C4). The active runtime reaches the other copies by fan-out through the store's list of artifacts.** Each entry of the list has `activate` and `deactivate` function pointers of its copy; the entry saves and restores per peer. A store with one artifact costs 0 indirect calls, a store with two or more about 4. Caching the TLS addresses of the peers is allowed later, only after a measurement.
* **D-5 (C5). The list of artifacts is a fixed array** (8 entries, a constant) **with a count published atomically** (release on `attach`, acquire on read); `attach` beyond it is refused with a reason. The list is **not** a second runtime. It exists to synchronise the small inline per-copy state that generated code reads without a function call (the stack limit in every prologue, the depth counters) with the runtime of the store. It replaces the `realloc`ed list of 8a, so `has_artifact` needs no lock any more.
* **D-6 (C6, reversed from the first plan). Every runtime function that generated code or the core can call goes through the runtime of the store**, including the exnref-table functions and the shared-memory functions, so that the runtime of a store is really one (nothing is allocated in one heap and released in another). The rule: whatever the core or generated code calls in the runtime is forwarded; **a feature added later adds its forwarders in the same step**. (The first plan of 8b left exnref and shared memory out; the maintainer reversed that.)
* **D-7 (C7, reversed from the first plan). Only the runtime of the store is initialised on a thread** (`wasm_rt_init`, `wasm_rt_init_thread`, the alternate stack of signals where the mode has one). A copy that is not the runtime of the store does **not** call `wasm_rt_init` or `wasm_rt_init_thread` for that thread: its inline state is synchronised (the stack limit variable, the depth counters). So there is no second alternate stack and no leak. This replaces the idea of re-installing each copy's stack. Record: D44.
* **D-8. The hot-path rule.** A change over 10 percent on case 1 or case 2 of `tools/bench_calls.py` against the baseline at the end of `docs/BENCHMARKS.md` (commit db92ac4, the same machine, medians of 3 runs, repeated in two runs) stops a sub-step. Cases 7 and 8 (position-independent shared libraries: B's `add` in A's store, and the same through a link) are added by 8b-1 and baselined at db92ac4.
  **Exception accepted by the maintainer 2026-11-04.** The gate on cases 7 and 8 (the path across two copies of the runtime, shared libraries) is accepted as an exception for 8b-2. The facts (`docs/BENCHMARKS.md`, "Step 8b-2" and "second round"): after 8b-2 case 7 is +24 percent and case 8 +13 percent against a fresh before-set of the same session (earlier: +44 and +32 before the entry was made inline); cases 1 and 2 (one artifact, the usual path) are within the rule (case 1 +0.8 percent against db92ac4, case 2 faster). The cost that is left is the dynamic TLS model of a position-independent library: about 1.6 ns per `__tls_get_addr`, seven accesses in case 7; with `-ftls-model=initial-exec` case 7 is +7 and case 8 -4 percent, but a product build cannot assume it because extensions are `dlopen`ed. It is a NEW capability: before 8b-2 a trap across copies was an abort, so no old number exists. Two further cuts are known and NOT done: a fused call (activate, enter and the unwind save in one call, about 3 accesses fewer) and a per-thread record of the other copy. The rule of 10 percent STAYS for cases 1 and 2.
### The design in terms
* **The runtime of a store** is a table `wasmext_runtime` in `src/wasmext/c/wasmext_runtime.h` (new): `size`, `version`, `layout`, `flags`; `trap`; `enter`, `leave`; the seven functions of the exceptions file (`load_exception`, `throw`, `get_unwind_target`, `set_unwind_target`, `exception_tag`, `exception_size`, `exception`); allocate, grow and free of memory, of shared memory and of the funcref, externref and exnref tables (three functions each for memory, shared memory and the funcref, externref and exnref tables: 15; with the seven of the exceptions and the trap, 23 forwarded names); `next_serial`. Fields are only added at the end. `flags` is proposed to carry the stack-check mode of the build (limit, guard, stock, depth) and `attach` to refuse a different mode (open question 2). Each copy has one table `wasmext_runtime_own_`, built from the renamed `wasmext_own_*` functions; its address is the identity of the runtime (one per artifact, hidden, defined by the file that defines `WASMEXT_DEFINE_THREAD_STATE`, as D33 teaches for a `static const`).
* **The active runtime** of a copy on a thread is `tls.rt`: the table to which the forwarders `wasm_rt_*` of THAT copy send the call; NULL means the copy's own table. Precisely:
  * it is a per-copy, per-thread pointer; the same thread has one `tls.rt` in each copy;
  * the core entry points set it: `WASMEXT_ENTER_STORE` (calls, `call_ref`, `instantiate`, the shim) and an *activation scope* (the same sequence with no jump buffer, for the paths that call a runtime function outside an entry: `memory_grow`, the table functions, `wasmext_tag_new`, `wasmext_extern_new`, the `close` of every member, `wasmext_instance_exception`; each takes the scope from the store it works on);
  * setting it on the entering copy is followed by the fan-out: for every other entry of the store's list, `activate` sets that copy's `tls.rt` (NULL if the table is its own) and synchronises its inline state; the previous values are saved per peer in the frame of the entry;
  * `leave` (and the path of a trap) restores what was saved, not NULL, so nested stores work: an entry into a store of another runtime saves the active runtime, sets its own, and restores the first at leave;
  * outside any entry or scope nobody should call a runtime function; a host that calls `wasm_rt_*` on a store directly does so on the runtime of its own copy.
* **`wasmext_tls`** is one hidden thread-local struct per copy (`rt`, `top`, `unwind_slot`, `ready`, `peers`), so that an entry costs one computation of a TLS address (in a shared library the TLS model is the dynamic one, and a computation costs a call; to be measured, not assumed). `top` is the innermost entry of the thread on this copy; `unwind_slot` is the address of `g_unwind_target` of the copy, published by the exceptions wrapper, so an entry saves and sets the target without a function call; `ready` has two bits, "inline state synchronised" and "runtime initialised" (D-7); `peers` is read as the record of the saved state of the peers during an activation (open question 4).
* **`wasmext_rt_entry`** is `{wasm_rt_jmp_buf buf; prev; saved_unwind}` (plus room for the saved state of the peers). The trap of the runtime of the store jumps to its innermost entry.
* **Fast path** of `WASMEXT_ENTER_STORE`: `store->head.rt == &wasmext_runtime_own_`, `tls.rt == NULL`, the thread ready, and the store has one artifact: direct calls, no fan-out. **Slow path:** save `tls.rt`, set it, make the thread ready as D-7 says, fan out with per-peer save, enter through `rt->enter`.
* **The list of artifacts** per D-5: `{identity, activate, deactivate}`. It enters the layout hash (the struct, the count, the array) and `_SWAPS` of `tests/test_artifacts.py:254`.
* **The temporary guard** (the refusal of a funcref of another artifact) stays until 8b-6.

#### 8b-3b. Copies made ready together (D-7)
* **Goal:** a thread that enters a store through a copy that is not the runtime of the store works in every variant, and no alternate stack leaks.
* **Design:** `activate` of an entry that is the runtime's own copy initialises it (`wasm_rt_init` once, bit "initialised"); any other entry only sets the inline bit (limit variable, depth counters). `thread_free` frees only what was initialised. Nothing else is registered.
* **Tests** r1 to r5: r1 the limit is set in both copies on a fresh thread (recursion in B and in A gives `EXHAUSTION`); r2 recursion in A reached from B gives `EXHAUSTION` (limit, guard, stock, depth); r3 a guard-page access in A reached from B gives `OOB` (limit, guard, stock); r4 a thread enters through both copies and ends: under LeakSanitizer there is no leak, and no "alternate stack was modified unexpectedly" (guard and stock); r5 `thread_free`, then the same thread enters again, then another thread, then `store_free` and a new store.
* **Mutations:** every copy calls `wasm_rt_init` (r4: the leak, the message of the runtime); the limit not synchronised in peers (r1); `thread_free` of a copy that was not initialised (r5).
* **Risk:** a thread that enters stores of two DIFFERENT runtimes, in guard or stock mode, still initialises two copies (two alternate stacks): D-7 closes the leak for one shared store only (the default `limit` mode has no alternate stack).

#### 8b-4. Depth-count platforms
* **Goal:** with `-DWASM_RT_STACK_DEPTH_COUNT=1` 10k traps, in one copy and across two, give no false `EXHAUSTION`; the test **fails before the fix**.
* **The defect, as read (not reproduced):** `WASM_RT_SAVE_STACK_DEPTH()` runs at every entry (`wasmext_glue.h:331`, `:356`) and sets `wasm_rt_saved_call_stack_depth = wasm_rt_call_stack_depth`; the macro stands in `wasm-rt-impl.h:38`; nothing restores `saved` at leave. A nested entry (a host function that calls back) overwrites the outer value; when the outer call then traps, `wasm_rt_trap` sets the depth to the inner value (`wasm-rt-impl.c:92`), which is the depth of the outer frames at the inner entry, not 0: the counter drifts up by that many per event until the limit of 500 (`wasm-rt.h`) gives a false `EXHAUSTION`. Across copies the trap restores only the counter of the copy that raised it. 8a built no test (test 11 above).
* **Design:** the entry saves `wasm_rt_saved_call_stack_depth` of the copy (in `wasmext_rt_entry`) and restores it at leave and on the trap path; the fan-out saves and restores the depth and the saved depth of each peer (`activate`/`deactivate`).
* **Tests:** d1 outer call, a host function re-enters and returns, the outer call traps, 10k times; d2 a trap in B's code reached from A's entry, 10k times. Both must fail on the unfixed code.
* **Mutation:** the restore at leave removed (d1 fails with a false `EXHAUSTION` after about 500 iterations).
* **Risk:** only the C variant `depth` can be run here; Windows (the real consumer) is seen by CI only.

#### 8c. The store keeps the artifacts loaded (planned, after 8b-7; D46 rule 5)

## Alternatives considered
* **Design 2, fan-out per store, no runtime of the store:** each entry sets the top and unwind target of every attached artifact (O(n) per entry). Traps are right;
  exceptions do not cross artifacts (they become `UNCAUGHT` at the entry and skip B's `catch`, against S0007); serials only less likely to collide. No binding rule.
* **Design 3, no shared trap state:** links only through shims; a funcref of another artifact is refused. Free on the hot path, but it is option (d) that D3 rules out. Usable as step 8a.
* Trampolines only (a) and same-artifact-only (c): ruled out by D3.
Design 1 was corrected on 2026-10-30 after the maintainer's remark: copies of the runtime exist for autonomy, and instances of all modules in a store use the runtime of that store; there is no binding of an artifact to a group for life. Recommended: design 1, built as **8a** (record, attach, serials, lifetimes, references in signatures, host tags) then **8b** (the group state).

## Measured alternative: an opaque store (decided 2026-10-30: not taken now)
Store operations through a table of pointers into one place, instead of inline code and struct layouts in each artifact, would remove the layout hash, the artifact list and the identity of the artifact. Prototype and numbers: `docs/experiments/opaque_store/` (three runs, Xeon 2.8 GHz, gcc 13.3): operations of the store through the table cost +7.8 to +10.1 percent on case 1 and +11.2 to +11.8 percent on case 2 of `tools/bench_calls.py` (about 1.5 ns per indirect call; 3 per call, 7 through a link). Over the 10 percent rule on case 2. The maintainer decided to keep the inline store with the layout hash. A hybrid (hot head inline, cold operations through a table) stays a possible later change, with its own measurement and Dn.

## Decisions (taken on 2026-10-30 by the model of Wasmtime, at the maintainer's instruction)
1. **Design 1.** In Wasmtime an exception thrown by code of one module is caught by a `try` of another in the same store, because the runtime is one. Design 2 cannot do it.
2. **The `exceptions` wrapper is acceptable under D6.** It is a wrapper outside the toolchain file (the manner of the `mem` wrapper); it is the only way to give the seven functions the runtime of the store.
3. **Host tags belong to the store** (in Wasmtime a `Tag` is made in a `Store` and lives and dies with it), not immortal. The process-global cell of an imported tag (D34) is set once as before and **cleared when the store that made the tag closes** (compare-and-swap from this tag to empty); while a store holds the tag, a second live store that imports the same name gets `WASMEXT_INST_TAG_HELD` (from `bind_export`; `WASMEXT_STORE_INCOMPATIBLE` stays for `attach`) with the reason. This is a limit of wasm2c (one global symbol per import name), noted in the spec and not hidden.
4. **Shared entry in every build** (Wasmtime has one entry for all). Kept unless the benchmark shows more than 10 percent on case 1 or 2; then a build option with a record flag is a new decision. (8b draft: the rule is D-8; the entry has a fast path for a store of one artifact on its own runtime.)
5. **Compatibility:** the same x of the ABI and the same layout hash (`attach` refuses otherwise). Not the same source fingerprint: that would forbid two releases of one x, and the ABI is one thing for alpha.
6. **A link re-throws an uncaught exception** in the importer (Wasmtime propagates an exception through every frame of the store). This changes S0007 ("exceptions do not cross links"); S0007 is changed first, in the same step.
7. **Depth counting** (Windows, Emscripten): the entry saves and restores the counters of the copies that have an instance in the store. Moving Windows to the stack-limit check is a separate step if it measures better. (8b draft: 8b-4; and the entry must also restore `wasm_rt_saved_call_stack_depth` of the copy, which today nothing does.)
8. **New Dn** (written with the step; 8b draft: D40 to D45 in `docs/DECISIONS.md`, status accepted on the maintainer's decisions of 2026-11-02 and kept in step with this draft): one supersedes D29; one amends D34 (host tags belong to the store, the cell is cleared at close); one records that D2's condition ("one party owns the traps of a group") is met; one records that the host is shared through the store (supersedes the line of `architecture.md`).
Known risks, not solved: MSVC `longjmp` across two DLLs (SEH) is untested; the artifact that made a store must stay loaded while any instance of the store runs (D46 rule 5: the store keeps a reference; step 8c).
