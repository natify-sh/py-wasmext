# How Wasmtime does Store, Linker, Caller and the state of WASI (read from the sources, 2026-10-26)

Read by a subagent in `/tmp/claude-0/wt_src` from the crates `wasmtime` 49.0.4 and `wasmtime-wasi` 49.0.4 (crates.io), the C API (`wasmtime-c-api-impl` 49.0.4) and the wheel of `wasmtime-py` 50.0.1 (a ctypes layer over the C API). Paths below are inside those; `(memory)` marks what is not from the code read. The aim: the `Context` of wasmext is a `Store` whose runtime is copied into every artifact and whose modules are AOT, so the design should follow what Wasmtime really does. Not read: `wasmtime-wasi-io`, `wasmtime-environ`, the docs and tests of wasmtime-py.

## What it says

1. **`Store<T>`** is a `Box<StoreInner<T>>` (`store.rs:196, 237`); `Store::new(engine, data)` (708), `data()` / `data_mut()` (826, 832). It holds many instances (a cap of 10 000 by default, `limits.rs:4`) and they **all share the one `T`**. A host function reaches `T` through `Caller<'a, T>` (`func.rs:2005`): `data()`, `data_mut()`, `engine()`, and `get_export(name)` (2042), a lookup in the exports of the **calling instance** (the use: `get_export("memory")`, "to implement passing of pointers or indices between core Wasm instances, where the callee needs to consult the caller's exports"). The same comment says that components avoid the need ("callees don't need to be aware of their callers, which promotes virtualizability of APIs").
2. **`Linker<T>`**: the definitions are independent of any store (`linker.rs:60-71, 488-497`: "compatible to instantiate into any Store"; `enum Definition { Extern, HostFunc(Arc<HostFunc>) }`, 127); defining an item that belongs to a store pins the linker to that store. Shadowing: `insert` (1021-1030) refuses a second definition of the same name unless `allow_shadowing(true)` (208), and then the newest wins; **the old definition is overwritten, and there is no way to call the previous one** (the same for the component linker). The functions of preview1 are methods of a **private** generated trait (`p1.rs:1184`; "None of the generated modules, traits, or types should be used externally", 853-856), so a user cannot call the original `fd_write`; the shape is `(&mut WasiP1Ctx, &mut GuestMemory, args)`. For preview2 the `Host` traits are public, so a p2 embedder can call the originals by name through the trait. wasmtime-py: `Linker.define_wasi()` (`_linker.py:116`) is `wasmtime_linker_define_wasi` -> `p1::add_to_linker_sync(linker, |ctx| ctx.wasi...)`, and to override one needs `allow_shadowing(True)` plus `define_func`; the original is not callable.
3. **The state of WASI is per Store**: `WasiCtxBuilder` (`ctx.rs:37`) holds args, env, `initial_cwd`, preopens (`preopened_dir`, 296), stdio, `socket_addr_check` (397), `allow_ip_name_lookup` (411), `allow_tcp` / `allow_udp`; the doc says a `WasiCtx` "is considered per-`Store` state", stored in the `T` and reached through `WasiView` (`view.rs:36-47`) with a separate `ResourceTable`. Preview1: `WasiP1Ctx { table, wasi, adapter, hostcall_fuel }` (`p1.rs:141`); the fd table is `Descriptors` (stdin, stdout, stderr first, then the preopens). The projection `f(&mut T) -> &mut WasiP1Ctx` takes no instance, so **two modules in one Store share args, env, preopens, stdio, the policy of the sockets and the fd table** (deduced from the signature; no sentence says it in words). **Different preopens for two modules mean two Stores** (the Linker is reusable across stores). The C API and wasmtime-py allow **one WASI config per Store** (`capi store.rs:236-243`; `store.set_wasi(WasiConfig)`), and a `WasiCtxBuilder` builds one `WasiCtx` only.
4. **Handles (preview2):** the handle numbers a guest sees are **per component instance** (`ResourceTables.guest`, `vm/component/resources.rs:58-61`); the host's own `ResourceTable` is **one per Store** (`host_table`, 63-69; `DEFAULT_MAX_COMPONENT_HANDLES = 100_000`). For a core module of preview1 the fd numbers are per `WasiP1Ctx`, so per Store.
5. **References belong to a Store:** every `Func`, `Table`, `Memory`, `Global`, `Tag`, `Instance` carries a `StoreId` (a process-wide atomic counter, `store/data.rs:140-170`) and an index; **using one with another Store panics** ("object used with the wrong store", `data.rs:193-213`; "considered a programmer error"), the fallible paths return errors (`func.rs:903`, `values.rs:234, 1119`). A `Store` is "intended to be a short-lived object... once an instance is created within a Store it will not be deallocated until the Store itself is dropped... recommended to have a Store correspond roughly to the lifetime of a 'main instance'" (`store.rs:139-146`). An `ExternRef` is a rooted GC reference (`Rooted<T>` / `RootScope`, `OwnedRooted<T>`, `gc/enabled/rooting.rs:60-130`).
6. **Traps:** calls between core instances in one Store are ordinary wasm-to-wasm calls (memory, not from the code). A trap unwinds to the nearest host-to-wasm entry (`catch_traps`, `vm/traphandlers.rs:457`); the call state is `CallThreadState` (509), a stack activation record linked through thread-local storage. The `Store` has `VMStoreContext` (`store.rs:464`) with the stack limits, fuel and epoch. **Only component code poisons a Store after a trap** (`ComponentStoreData.trapped`, `component/store.rs:42, 324-336`); a trap in a core module does not.
7. **wasmtime-py:** `Store(engine, data)`; `store.set_wasi(WasiConfig)` (the config: `argv`, `env`, `stdin_file`, `stdout_custom`, `inherit_*`, `preopen_dir(path, guest_path, fs_mutable)`); `Linker.define_func(module, name, FuncType, func, access_caller=False)` (`_linker.py:64`): **the host function gets a `Caller` first only when `access_caller=True`**; `caller["memory"]` is valid only during the call.

## What it means for wasmext

- **The state of WASI belongs to the Context, as in Wasmtime** (one set of args, env, preopens, stdio, one table of descriptors, shared by all its instances); a different config means a different Context. Where the config is **given** is a decision (below).
- **No built-in "original" in Wasmtime**; ours is better: each function of the host is a plain function of (state, memory, arguments), so a replacement can call it. The memory of the caller is known to the trampoline (it has the instance), and the Context can note "the instance in call" so that an original taken at the level of the Context reaches the right memory.
- **`Caller` exists because host functions are shared by many instances and must be told who called**; Wasmtime makes it **opt-in per host function** (`access_caller=True`). That is the same as our deferred `caller` as a mark on the function (`fn.__wasm_caller__ = True`): confirmed as the right shape.
- **Context id on every reference, failing loudly across contexts** (`LinkError`), as Wasmtime panics/errors across stores.
- **The members of a context only grow** and a context is short-lived by design; a context for each batch of work: as Wasmtime's own advice.
- A trap in a core module does not poison the Context (policy; Wasmtime poisons for components only).
